# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

Vibe Coder — a Codio Custom Assistant for Grade 8 tech that builds HTML/CSS/JS sites from student design specs. **Read the parent `../CLAUDE.md` first** for the shared coach architecture, API quirks, and deployment flow. This file covers only what is specific to this coach.

## The inverted rule

Every other coach in this workspace enforces "never write complete programs." **This coach intentionally does the opposite** — it writes complete, working files, because the learning objective is spec-writing, not coding. Do not "fix" it by adding the no-solutions guardrail. The pedagogical pressure lives elsewhere: the system prompt makes the coach interrogate vague specs (clarifying questions, or an explicit ASSUMPTIONS list) and build *only* what the spec says.

## Commands

```bash
node --check index.js
node test/run-test.js    # stubs codioIDE, drives a full 2-turn build, tests parser + path safety
```

## Architecture specifics

- **File output protocol**: the LLM emits complete files between `===FILE: path===` / `===END FILE===` marker lines. `parseFilesFromResponse()` extracts them, tolerates stray code fences around bodies, replaces bodies with `[file: path]` stubs in the prose (stubs are what's shown and kept in message history — the refreshed `messages[0]` workspace block carries current file state instead).
- **`ask()` has a hard output-length cap** (observed live, Aug 2026: a full game's script.js was cut off mid-file). The parser detects a trailing `===FILE:` block with no END marker, and `runTurn()` immediately re-asks for just that file (up to `MAX_CONTINUES` extra asks, bookkeeping messages kept out of real history); partial files are never written. The system prompt (v1.5.2) also **mandates splitting every build into small files by JOB** (e.g. a canvas game → `input.js`/`game.js`/`draw.js`, each ≲60 lines, in dependency order) rather than "try to be small" — readability isn't the goal (students mostly don't read the JS; the objective is spec-writing), but small files survive the cap and recover cleanly if one is cut off. Split *by job, not per function*: with plain `<script>` tags files share globals, so more files = more cross-file coupling = more of the exact consistency-drift surface the recovery fix guards. Note the cap is on the *whole* response, so splitting doesn't stop the initial truncation — it makes the loss a small, recoverable file instead of a whole monolith. If recovery still fails, the student is told to ask for a shorter resend.
- **`files.add()` cannot overwrite an existing file** (observed live, Aug 2026: turn-1 writes succeeded, turn-2 rewrites of the same paths rejected). There is no update method, so `writeFiles()` falls back to `deleteFiles([path])` + `add()` — the sole permitted `deleteFiles` use, and only for a path it is immediately re-adding with new content.
- **`deleteFiles()`+`add()` overwrites are RACY and can silently land 0-byte files** (observed live Aug 2026: an iteration turn's overwrites of `game.js`, `draw.js` AND the shared `.coach-log.json` all landed empty — the deletes succeeded, the `add()`s wrote nothing, and `add()` *threw nothing*, so the coach reported success and destroyed the files; likely worsened by v1.5.2's fire-and-forget log write racing the site writes). Fix (v1.5.3): `addVerified()` reads every write back (via `readbackOk()`, a length check tolerant of newline normalization) and, on an empty/short read, pauses (`delay`, lets a delete settle / a racing write finish) and retries `deleteFiles`+`add` up to 5×. The retry self-heals transient concurrency corruption **without** a global file-lock (which would let a hung log write stall the next build). All files-API calls are wrapped in `withTimeout()` so a hung op can't freeze the coach. `saveSessionHistory()` uses the same verified write so the shared log can't be zeroed. Regression-tested ("empty write retried until real content lands").
- Codio's chat panel renders `write()` output as markdown — displayed code shows curly quotes and eaten `++`. That's display-only; files are written from the raw `ask()` result and are clean.
- **Path safety**: `isSafePath()` — writable extensions only (`.html/.css/.js/.svg/.md/.txt`), no `/` prefix, no `..`, no `\`, max 3 path segments, max 8 files per turn. Keep this strict; the LLM's output is untrusted.
- **Writes** go through `codioIDE.files.add(path, content)` (it's the only coach that writes), with the verified delete+re-add overwrite fallback above. Never call `deleteFiles` for any other purpose. If a write ultimately fails (rare, post-v1.5.3), the coach shows a **short** "couldn't save X — ask me to try saving again" line and does NOT dump the files' source into the chat (v1.5.4): a wall of code overwhelms a middle schooler and they can't reliably hand-copy several files; asking again regenerates and re-writes, which usually clears a transient failure. Keep this gentle — don't restore the full-code copy-paste dump.
- **Workspace reading**: `gatherWorkspaceText()` reads spec docs (`.md/.txt`), SVG design exports (as text — the model reads layout/labels from SVG markup), and current site files, budgeted at 20k chars / 8k per file (lowered from 40k/12k in v1.5.2 — this block is rebuilt and resent as `messages[0]` *every turn*, so it's the dominant per-turn payload; keep it lean). `dropRedundantReadme()` skips the assignment's own `README.md` when the student has other spec docs, so it isn't re-embedded every turn (kept only if it's the sole doc). `gatherWorkspaceText({includeSite:false})` / `buildContextMessage(input, {includeSite:false})` omit the current-site files — used for the **truncation-recovery ask**, where `companionFilesBlock()` already carries the just-built files verbatim, so the recovery ask uses a *slim* first message (spec + guide only) instead of resending the whole site 2–3× per build. `ask()` messages are text-only (no image blocks; confirmed against the coachBot docs, Aug 2026), so binaries are listed, never read — in two distinct buckets: PNG/JPG/GIF/WebP are surfaced as *usable assets* (the site can reference them by relative path; the prompt treats art source as a spec dimension — when a spec involves characters/sprites and no matching image exists, the model asks "shapes drawn from code, or will you upload an image?" as a clarifying question, with upload instructions when they choose images); `.fig`/PDF are *design-only* (the model asks for an SVG export or a description).
- **Session log**: `.coach-log.json` in the workspace (dot-prefixed → skipped by `collectPaths`, so it never enters LLM context) — the **shared** log all eight coaches append to (see the parent `../CLAUDE.md` "Session Logging"). A JSON array of per-session summaries written after every turn via the same delete+re-add pattern, for autograder consumption; entries are tagged with `coach: "vibe-coder"`, and this coach additionally records files written and failure counts (`filesWritten`/`writeFailures`/`filesLostToLengthLimit`) that the Q&A coaches don't. Old sessions are never dropped (always appended). Logging is wrapped so it can never break the coach — and, since v1.5.2, is also **non-blocking**: per-turn saves go through `queueSave()` (fire-and-forget promise chain), never `await`ed in the input loop, so a stalled `.coach-log.json` write can't freeze the coach (this was the "lost the ability to respond" bug — see the parent `../CLAUDE.md` "Session Logging" for the shared pattern applied to all eight coaches). Only the end-of-session flush is awaited. This is the only record of student questions anywhere: Codio's platform coach-log export logs only `userPrompt`, which messages-based coaches leave empty (verified in a real export, Aug 2026).
- **Continuation resends must preserve cross-file consistency**: the recovery ask now **shows the model the already-saved files verbatim** (via `companionFilesBlock()`), not just tells it they exist, and instructs it to reuse their exact ids/classes/functions and wire up every control they contain. Telling-without-showing was insufficient: at continuation time `messages[0]`'s workspace snapshot predates this turn's writes (`writeFiles()` runs *after* the loop) and the stubbed prose replaces file bodies with `[file: …]` stubs — so the recovery model was **blind to the HTML it had to match** and reinvented ids the HTML lacked. (v1.3.0 first added the *tell*; v1.5.1 added the *show* after a real session — Apple Catcher, Aug 2026 — where a truncated `script.js` was resent referencing a `#startBtn`/`#score` that `index.html` never had, throwing `TypeError` at load and leaving the student a blank canvas. Regression-tested in `test/run-test.js`.)
- Shares the standard skeleton: `buildContextMessage()` refresh before every `ask()`, first-message + last-8 trimming, version banner + "version" easter egg, exit phrases.
- `window.__vibeCoderTest` exposes internals solely for the Node harness.
